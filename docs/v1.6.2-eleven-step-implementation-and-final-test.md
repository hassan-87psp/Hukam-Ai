# HUKM AI v1.6.2 — Personal WhatsApp Desktop 11-step implementation & final test

> This is the source-level work contract. Passing CI validates simulations and packaging, **not live WhatsApp on the owner's laptop**. No WhatsApp account, chat, or installation is available in CI.

## Eleven implementation areas

1. **Windows Controller version and process audit:** retain the local single-instance mutex; expose running controllerVersion, configured/effective WhatsApp mode, capability status, UIA capability in owner-approved diagnostics. Devices displays the version from a real WebSocket hello.
2. **Desktop default:** Personal WhatsApp Desktop is always the default; legacy `whatsapp_mode=web` is ignored and migrated on load. WhatsApp Web remains available only on an explicit `WhatsApp Web` request. Never open Web automatically while drafting.
3. **Multi-step command router:** `WhatsApp Desktop on laptop and check msg` is two reviewed steps: `whatsapp.open`, `whatsapp.unread_senders` (separate owner approval). An explicit numeric question yields `whatsapp.open`, `whatsapp.check`. No pretending unread count is equivalent to message text.
4. **Native Windows app launch:** focus an existing verified native WhatsApp main window; otherwise launch a known installed executable or an exact WhatsApp Windows Start app. The `whatsapp:` protocol handler is deliberately not used, since it may be redirected to Web. Chrome tabs and unrelated WebView2 windows are not valid native sessions.
5. **Windows accessibility:** owner-approved diagnostics expose UIA-installed, tree readable, filter accessible, Search accessible and numeric unread badge readable flags. No contacts/message text/clipboard/screenshot content is returned in diagnostics.
6. **Unread status:** count only explicit WhatsApp numeric UIA badge or native window-title indicator. A taskbar notification bubble is NOT a verified total. Sender scan needs an owner approval. Names visible after an Unread click are tagged unverified if the UIA selected state cannot be established; never label them confirmed unread.
7. **Message reads:** named chat uses approved `whatsapp.select_chat` with exact UIA sidebar search and verified right-hand header followed by separately approved `whatsapp.read_selected` pinned to the same contact. No partial-name match or background inbox scrape.
8. **Question/answer memory:** keep existing owner/project-scoped SQLite conversations. After a successful visible-sender scan, persist a new follow-up question ("kis contact ka visible message parhun?") without storing sender names in the planner's Gemini context. The web app periodically restores pending question state.
9. **Drafts and sending:** `whatsapp.compose` no longer requires a saved phone number. It selects the named native chat and drafts with zero sending. Existing separately approved `send_reviewed` / attachment send paths preserve exact contact/file checks, and never automatically retry uncertain sends.
10. **Error recovery:** Relay keeps the Controller's actual verified/unverified reason instead of replacing every WhatsApp result with a generic English string. Frontend explains verification, accessibility or launch failures in Roman Urdu. No guessing or fake green success.
11. **Release/version synchronization:** Controller and Relay version, installer archive and scripts use v1.6.2. CI should cover typecheck, unit/integration suites, production build, Windows syntax, simulation, frozen Windows exe and isolated installer smoke test. GitHub Pages deployment and Render backend release MUST be verified separately. Connecting a signed-in Personal WhatsApp account and final real-Windows acceptance remain the user's explicitly deferred end-to-end test.

## Required final live acceptance (after implementation and automated checks)

* Close all old HUKM Controller windows. Extract v1.6.2 ZIP, run `INSTALL_OR_UPDATE.cmd`, `VERIFY_HUKM.cmd`, `START_HUKM.cmd`. Device version must say **1.6.2**.
* HUKM `diagnostics.probe` (with approval): verify `controllerVersion`, `effectiveWhatsAppDefault`, native process/window, `whatsappAccessibilityTreeReadable`, `whatsappUnreadFilterAccessible`, `whatsappSearchControlAccessible`, `whatsappUnreadBadgeReadable`.
* `WhatsApp Desktop kholo` focuses the existing native signed-in desktop, **never Chrome**. `WhatsApp Web kholo` opens browser only on that explicit wording.
* `WhatsApp Desktop on laptop and check msg` must create a **two-step reviewed plan**; user sees open Desktop first, then an approved visible Unread sender scan. No single unread-count shortcut.
* `WhatsApp Desktop kholo aur check karo kitne unread msgs hain` must create native open plus numeric check; if count is not exposed, say **unknown (not zero)** and offer verified diagnostics/fallback, never report guessed taskbar bubble count.
* For a named contact, select and reverify header before showing currently visible chat text. Switching to a different chat between approvals must fail closed. Contact or content ambiguity must not cause Send.
* After approved sender scan, HUKM must ask which contact to read and understand `Ali ka` in context after a normal page refresh.
* `Ali ko reply likho ...` must create a reviewed unsent native Desktop draft even when Ali is not separately saved in HUKM's phone-number settings.
* Send remains separately approved, no auto retries of uncertain outcomes. Attachment previews must require separate file confirmation.
* Test screen lock, Desktop window missing, empty/ambiguous UIA controls, no installation, no internet, old controller version, startup reconnect and disconnected devices. No false success or leaked message contents in diagnostics.
* Verify actual https://hukm-ai-relay.onrender.com backend `/api/health` version and Pages frontend separately; a passing GitHub CI workflow is **not** deployment proof.

## Known limitations

Personal WhatsApp Desktop does not expose a stable, official automation API for private chat read/count. Windows UIA may vary by WhatsApp version, account, display DPI, localization, screen-reader configuration and whether the app is foreground/unlocked. A non-accessible Unread indicator or message row remains unsupported, not fixed by inventing a number. These boundaries remain visible in HUKM's results. `read_selected` transfers approved visible chat text to the authenticated HUKM account and stores it in history; `read_visible` reads only locally without transferring text. Real user-machine testing is intentionally deferred until after all code steps.
