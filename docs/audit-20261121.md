# HUKM AI — Audit and operator rebuild, 21 November 2026

## What the user needs

One website-controlled Windows assistant, connected after sign-in to the Windows Controller:
natural Roman Urdu/Urdu/English commands; full screen/browser workflow; Google and Outlook
calendar scheduling; WhatsApp unread messages, replies and file sending; ChatGPT-based banners
and scripts; permanent Projects similar to ChatGPT with saved Chrome profile, ChatGPT Project,
instructions, notes and memory; one tested Windows installer with safe updates.

## Architecture implemented in v1.3.0 branch

- Existing relay, owner authentication, device pairing, command validation, approvals,
  emergency stop, private SQLite backup preserved.
- `projects`, `project_notes`, `project_messages` private tables, owner-scoped authenticated routes,
  Projects UI on desktop/mobile. Profiles are real Chrome directories (`Default`/`Profile N`).
- Gemini project conversation uses saved instructions, notes and recent saved history. The UI
  informs owner that project context goes to Google for AI calls. No device tokens or cookies.
- `operator_plans` and `operator_runs` durable tables: one- to five-step Gemini proposals;
  allowlisted structured actions, relay and controller revalidation, per-action owner approval,
  status polling and cancel. No shell/terminal/file deletion or model-generated click coordinates.
- Notepad typing restricted to visible, active `notepad.exe`; multiline text permitted.
- Existing Chrome profile directory checked before opening ChatGPT/Calendar URLs. No profile
  sessions, passwords or cookies are read, saved or cloned.
- Input-success without independent application observation is `unverified`, not "done".
- Single consolidated Windows setup scripts copy EXE to a permanent folder; prior EXE rollback,
  pairing preserved, no automatic deletion of any old data.

## Security and privacy constraints

1. Never take arbitrary shell command output from Gemini and execute it.
2. Model output is untrusted: every action and arg validated by command-protocol and Python mirror.
3. Every operator plan needs an explicit Run action; keyboard and sensitive actions need separate approval.
4. Only logged-in owner can read Projects, plans, task runs. Authentication and CSRF apply to mutations.
5. WhatsApp message contents, OTPs, financial data and screen snapshots do not go to Gemini automatically.
6. Project instructions/notes may be transmitted to Gemini only for relevant project conversations/plans.
7. No misleading "completed" when Windows only accepted input or when unread count cannot be verified.
8. Device pairing and existing local config in APPDATA are not replaced by new controller ZIP.
9. Do not delete old extracted relay directories with `data` or `.env` before backing them up.
10. Browser profile automation requires local interactive desktop and existing sign-in.

## Known limits and explicit pending work

The code currently does **not** implement universal visual observation / GUI planning,
reliable personal WhatsApp reading/sending with file attachments, official Calendar OAuth
event creation, ChatGPT image-generation/download automation, multi-screen verified app results,
automatic updates without user interaction, model fine-tuning, or a guarantee that websites
permit browser automation. These cannot honestly be called complete until implemented,
authorized by the user as needed, and verified with real accounts and laptop.

This file is an audit and acceptance contract, not a claim all tests passed.
